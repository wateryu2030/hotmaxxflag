# 好特卖运营小程序功能建议书

> 基于当前 Flask 看板、`daily_category_stats` 预聚合表及既有 API 结构整理；与提示词中部分路径/字段名不一致处，以本仓库代码为准。

---

## 1. 用户画像与核心需求

### 1.1 门店店长

- 每日快速确认：**销售额、毛利、毛利率**是否异常。
- 知道**哪些大类/中类**拖后腿（低毛利、负毛利 SKU 数量）。
- 需要**可行动的短句**（如「服装大类毛利率低于近 30 天中位数」），而非复杂报表。

### 1.2 区域经理（多店视角，若后续支持 `store_id` 切换）

- 对比管辖门店的 **KPI 与 TOP 品类结构**（依赖后端多店权限模型，当前 Web 以 `STORE_ID` 为主时需扩展）。
- 关注**预警汇总**（低毛利、人力强度异常等）。
- 轻量下钻到中类即可，不做 SKU 级深度分析。

### 1.3 运营专员

- 跟进**品类健康**（贡献结构、四象限结论的「一句话摘要」）。
- 查看**映射健康/未映射大类**（与人力分析一致）。
- 需要**订阅消息**在关键阈值触发时被动提醒。

## 2. 功能模块建议（P0 / P1 / P2）

说明：实际路径以代码为准。KPI 为 **`GET /api/kpi`**（非 `/api/sales/kpi`）；品类相关为 **`/api/category_rank*`** 系列；人力为 **`/api/labor_analysis/*`**、**`GET /api/four_quadrant`**；已有 **`GET /api/mobile/dashboard`**。

**`daily_category_stats` 实际字段**（见 `scripts/27_daily_category_stats.sql`）：`store_id`, `data_date`, `category_large_code`, `category_large`, `category_mid_code`, `category_mid`, `sale_qty`, `sale_amount`, `sale_cost`, `gross_profit`（无 `sale_date` 列名，逻辑上即销售日）。

### P0（必须有）

| 功能 | 简述 | 后端 API | 前端交互要点 | 数据来源 |
|------|------|-----------|----------------|----------|
| 首页驾驶舱 | 1 屏展示 1～2 个核心 KPI + TOP 品类 + 负毛利 SKU 数 | **已有** `GET /api/mobile/dashboard`；可扩展 `store_id`、`days` 参数 | 大数字卡片 + 横向滑动 TOP5 列表；点击进入「品类概览」 | 优先 **`daily_category_stats`**（与现实现一致），否则 `t_htma_sale` |
| 登录与身份 | 与现有飞书体系对齐或小程序独立鉴权 | **已有** `/api/auth/*`；小程序需 **code2session 或 WebView 登录态同步** 方案（需新增设计） | 一键登录、过期静默刷新 | 会话 + 模块权限同 Web |
| 日期范围 | 近 7 / 30 天切换 | **新增建议** `GET /api/mobile/summary?days=7|30`（聚合参数与 dashboard 一致） | 顶部 Segmented；小屏默认 30 天 | 同上，**仅查预聚合表** |

### P1（强烈建议）

| 功能 | 简述 | 后端 API | 前端交互要点 | 数据来源 |
|------|------|-----------|----------------|----------|
| 品类概览（大类） | 销售额、毛利、毛利率排行 | **已有** `GET /api/category_rank`、`GET /api/category_rank_by_large`；建议 **新增** `GET /api/mobile/category_large?start_date&end_date` **只读 daily_category_stats** | 纵向列表 + 条形图；点击进中类 | **`daily_category_stats`** `GROUP BY category_large` |
| 品类下钻（中类） | 单大类下中类列表 | **新增** `GET /api/mobile/category_mid?large_code=&start_date&end_date` | 二级页，单列指标为主 | **`daily_category_stats`** |
| 人力与四象限摘要 | 不在小屏做全表，只做摘要 | **已有** `GET /api/labor_analysis/overview`、`GET /api/four_quadrant`、`GET /api/labor_analysis/mapping_health` | 每页 1 图 + 1 表；四象限用 **散点 + 中位数线**，点数多时可后端抽样（待实现） | 现 API 多为 `t_htma_sale` + 人力表；四象限计算重，建议 **服务端缓存 2～5 分钟** |
| 预警与订阅消息 | 低毛利大类、负毛利 SKU 数超阈、映射缺失等 | **新增** `GET /api/mobile/alerts`（规则配置可读 DB 或 YAML）；**微信订阅消息**走模板 ID + 用户触发订阅 | 首页「今日提醒」列表 +「去开启订阅」引导 | 预聚合表算毛利率 + 现有负毛利统计逻辑；人力用 mapping_health |

### P2（可后续迭代）

| 功能 | 简述 | 后端 API | 前端交互要点 | 数据来源 |
|------|------|-----------|----------------|----------|
| 贡献结构简版 | 大类销额占比 vs 毛利占比 | **已有** `GET /api/contribution_structure`（`routes_sales`） | 单饼或叠条，禁止一屏多图 | `t_htma_sale` 或中期改为预聚合汇总 |
| 负毛利 SKU 列表（简） | 仅列表前 N 条 | **已有** `GET /api/negative_margin_items?limit=&offset=` | 无限滚动，默认 50 | `t_htma_sale` |
| Web 深度分析跳转 | 复杂页 H5 | 配置 `web_base_url` + 路径参数 | 「在电脑上看完整分析」 | Web `index.html` / `labor_analysis.html` |

**不包含**：订单级连带率、复购率、会员路径等（当前无订单粒度数据）。

## 3. 数据接口设计建议（小程序专用，≥5 个）

以下在 **`/api/mobile/`** 前缀下扩展，与现有 `GET /api/mobile/dashboard` 风格统一（`success` + 业务字段）；鉴权与 Web 一致。

### 3.1 `GET /api/mobile/dashboard`（已有，可扩展）

**Query**：`store_id`（可选，多店时）、`days`（默认 30，最大 90）。

**响应示例**：

```json
{
  "success": true,
  "range": {"start_date": "2026-03-27", "end_date": "2026-04-25"},
  "kpi": {
    "total_sale_amount": 2019016.38,
    "total_gross_profit": 692007.52,
    "avg_profit_rate_pct": 34.27
  },
  "top_categories": [{"name": "服装", "sale_amount": 996595.4}],
  "negative_margin_sku_count": 22,
  "data_source": "daily_category_stats"
}
```

### 3.2 `GET /api/mobile/category_large`（建议新增）

**Query**：`start_date`, `end_date`, `store_id?`, `limit`（默认 20）。

**返回字段示例**：`items[].category_large`, `category_large_code`, `sale_amount`, `gross_profit`, `margin_pct`, `sale_qty`。

**SQL 思路**：`FROM daily_category_stats WHERE store_id=? AND data_date BETWEEN ? AND ? GROUP BY category_large_code`（名称取 `MAX(category_large)`）。

### 3.3 `GET /api/mobile/category_mid`（建议新增）

**Query**：`category_large_code`（必填）, `start_date`, `end_date`。

**返回**：该大类下中类排行，字段含 `category_mid`, `sale_amount`, `gross_profit`, `margin_pct`。

### 3.4 `GET /api/mobile/trend`（建议新增）

**Query**：`metric=sale|profit|margin`, `days`（≤90）。

**返回**：`series[{date, value}]` 按日汇总，**仅查预聚合表** `GROUP BY data_date`。

### 3.5 `GET /api/mobile/alerts`（建议新增）

**Query**：`store_id?`。

**返回示例**：

```json
{
  "success": true,
  "alerts": [
    {"type": "low_margin_large", "title": "鞋子大类毛利率偏低", "detail": "近30天 18.2%，低于阈值 20%"},
    {"type": "unmapped_sales", "title": "有大类销售未配置人力映射", "count": 3}
  ]
}
```

规则引擎可先硬编码阈值 + 调用现有 `mapping_health` 与预聚合毛利率。

### 3.6 `GET /api/mobile/labor_summary`（建议新增，P1）

**Query**：`start_date`, `end_date`。

**返回**：封装 `overview` 核心数字为扁平 JSON，减少小程序端多次请求。

## 4. 与现有 Web 端的关系

- **小程序定位**：**看板 + 预警 + 轻决策**（1～2 指标/屏、少参数、秒开）。
- **Web 端保留**：多 Tab 联动、ECharts 重型图、品类下钻全路径、导入/审批、税务与分润等 **操作型与复杂分析**。
- **协同方式**：小程序卡片「详情」跳转 **内置 WebView**（带登录 Cookie 或 token）打开指定路由，如 `/labor_analysis?start_date=…`；或复制链接到企业微信/浏览器。

## 5. 技术实现注意事项

| 主题 | 建议 |
|------|------|
| **性能** | 列表/趋势 **一律优先 `daily_category_stats`**；`days` 上限 90；列表 `limit` 分页。与现网 `extensions.SimpleTTLCache` 一致，mobile 接口可 **120s～300s** 服务端缓存。 |
| **预加载** | 小程序 `onLaunch` 仅请求 `dashboard`；进入二级页再请求 `category_large` / `trend`，避免首屏并发过多。 |
| **登录鉴权** | 与飞书 OAuth 对齐：小程序可用 **企业主体** 绑定「小程序登录」+ 后端换 user，或与 Web **共享 session**（需域名与 Cookie 策略设计）。未登录统一 `401` + `login_required`。 |
| **订阅消息** | 仅用户点击「订阅」后下发；模板与文案需微信审核；阈值触发建议 **服务端定时任务** 写「待发送队列」，由用户在小程序内合并触发（合规）。 |
| **版本与配置** | 阈值、模板 ID、H5 基地址放 **远端配置**（或环境变量），支持热更新免审小程序逻辑（仅读配置）。 |
| **数据一致性** | 预聚合有 **刷新延迟**；接口返回 `data_source` 与可选 `stats_as_of`（预聚合 `MAX(updated_at)`）增强可信度。 |

## 6. 分阶段实施路线图（每阶段约两周）

### 版本 1（MVP-1）：能看、能登录

- 飞书/账号体系与小程序打通（最小闭环）。
- 首页：`/api/mobile/dashboard` + 日期 `days` 参数扩展。
- 静态「今日提醒」占位（无订阅）。

### 版本 2（MVP-2）：品类与趋势

- 新增 `category_large` / `category_mid` / `trend`（全部走 `daily_category_stats`）。
- 负毛利 SKU 简列表（调用 `negative_margin_items` 小 limit）。
- 开启服务端缓存与 `stats_as_of`。

### 版本 3（MVP-3）：预警与人力摘要

- `alerts` + 规则表或配置化阈值。
- 微信订阅消息（低毛利、未映射人力等模板）。
- `labor_summary` 与四象限「一句话结论」；WebView 跳转深度分析页。
